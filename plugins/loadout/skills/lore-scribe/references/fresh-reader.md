# The fresh-reader test

A writer can't unknow what they know, so ask someone who knows nothing. Start one subagent, never a fork, because a fork inherits this conversation. Use a fast model. Give it only the page's path and this brief:

> Read this file as a stranger who found it by chance. You know nothing about the project. Stop reading the moment you'd stop in real life.
>
> Report four things, in plain sentences:
> 1. From the first screen alone (about 25 lines): what is this, and who is it for?
> 2. The exact line where you lost interest or got confused, and why.
> 3. What you'd do next, if anything.
> 4. Any word or name you had to guess at.

Compare answer 1 with what the page is meant to say. A wrong or vague answer means the opening failed, however good the rest is. Fix the opening first, then anything named in answer 2 or 4.

Run it once more only if you rewrote the opening. Report what the reader said and what you changed, and keep your own view of the page out of the brief.
