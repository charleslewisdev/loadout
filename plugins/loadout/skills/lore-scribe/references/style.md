# Style reference

A short distillation of the [Google developer documentation style guide](https://developers.google.com/style/), reworded and cut to what a model gets wrong. The guide's content is licensed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). This file is an adaptation, and it adds this repo's own rules. Google doesn't endorse it.

## Wording

- Use active voice and present tense. Say who does what.
- Use "you" for the reader. Avoid "we" and "let's" in instructions.
- Keep sentences short, about twenty words, with one idea each.
- Use plain words: "use", not "utilize"; "start", not "initiate".
- Use the same word for the same thing on every page.
- Spell out an abbreviation the first time, unless every reader knows it.
- Cut "simply", "just", "easily", "please" and "note that". What's easy for you may not be for the reader.
- Avoid future tense for what a product does today, and avoid "currently" and "new", which go stale.

## Structure

- Use sentence case for headings, and start task headings with a verb.
- Don't skip heading levels, and put text between a heading and its first subheading.
- Use numbered lists for steps in order, and bullets for everything else.
- Give each step one action. Put the condition before the instruction: "To save, press Enter."
- Keep lists parallel: every item starts the same way.
- Use a table only when items share the same attributes.

## Links and code

- Write link text that says where it goes. Never "click here" or a bare URL.
- Put commands, paths, flags and identifiers in code font.
- Introduce a code block with a sentence, and make it copy and paste as shown.
- Show placeholders in a form the reader can spot, and say what to replace.
- State the expected result of a command when it isn't obvious.

## Machine prose to avoid

- "It is not X, it is Y" framing, and invented aphorisms.
- Em-dashes: use a comma, a colon or a new sentence.
- Filler: "load-bearing", "genuinely", "honest", "nuanced", "the real question".
- A closing paragraph that repeats the page.
